# Handoff: SALONRINK ミニアプリ／ホーム改定 ＋ マイカルテ再設計

## Overview

LINEミニアプリ（app/liff/ 配下、現状の入口は /liff/pre-counseling；2026-08-28 実確認）の「ホーム」と「マイカルテ」を改定する設計です。目的は2つ。

1. マイカルテを「来店前に1回だけ入力するフォーム」から「普段の記録が溜まる場所」に変え、送信時の入力量を減らす。
2. 長い1画面スクロールを、4タブ＋4ステップに分解して離脱を減らす。

加えて、写真の長期保存を有料枠にする課金設計を含みます。

## About the Design Files

このバンドルに含まれる `.dc.html` は **HTMLで作った設計リファレンス**です。見た目と挙動の意図を示すプロトタイプであり、本番にそのまま貼るコードではありません。実装は SalonRink の既存環境（Next.js App Router / Vercel / Supabase）で、既存のコンポーネントとスタイル規約に沿って**作り直してください**。

注意（既存の踏み方）:
- `app` ディレクトリの位置はリポジトリで実確認する。位置違いは404の定番原因。
- `/neo` 配下の redirect を触るときは exact-match に限定。LINE Flexボタンの遷移先（`/neo/diagnosis.html`, `/neo/ec.html`）を壊さないこと。
- 美容・白髪に関わる表示文言は薬機法サニタイズを通す。効能の断定表現を置かない。

## Fidelity

**High-fidelity（hifi）**。色・タイポ・余白・角丸は下記 Design Tokens の値がそのまま指定値です。ダミー写真はベージュのプレースホルダで表現しているので、そこは実データ・実画像に置き換えてください。

## Interactions & Behavior

- **ステップ遷移**: 次へ／戻るで1〜4を移動。各ステップの入力は**都度自動保存**（下書き）。離脱後はホームの「事前カルテを仕上げる」から再開。
- **自動反映**: きろくの記録（写真・スコア・製品・前回施術・感想）と、設定の「わたしの情報」（履歴・アレルギー）を下書きに読み込む。ユーザーが編集した項目は自動反映で上書きしない。
- **充実度%**: 必須項目（希望メニュー・イメージ or 自由入力・悩み）と任意項目の充足率。ホームと Step ヘッダーで同じ値を出す。
- **チップ**: タップでトグル。選択時のスタイルは上記。悩み・避けたいことは複数選択、来店の目的は単一選択。
- **写真**: 端末カメラ／アルバムから追加。アップロード中はプレースホルダにスピナー。失敗時はタイル上に再試行。
- **保存期限**: 期限まで7日以内の写真にバッジ。期限到達で自動削除、削除7日前と当日にLINE通知。
- **送信**: LINEのトークに送信。送信後はホームのカードが「送信済み ／ 返信待ち」に変わる。事前返信が届いたらタイムラインに美容師コメントとして追加。
- **IG型タイムライン（きろく内）**: タブ ハイライト／グリッド／来店だけ。ハイライトは最近3件のグリッド＋フィード投稿。投稿は**非公開が既定**、来店前にまとめて共有する操作で初めてサロンに渡る。

## State Management

- `draftKarte`: { photos[], concerns[], images[], imageNote, avoid[], menus[], purpose, freeText, replyPref, destination } — 自動保存（Supabase、ユーザー×来店予定単位）。
- `profile`: { allergies[], treatmentHistory[] } — 設定で編集、カルテに読み出し。
- `records`: { photos[], products[], stylingNotes[], scores[], feedback[] } — きろく。
- `plan`: { tier: 'free' | 'paid', photoCount, photoLimit, retentionDays } — 保存枠の判定。
- `scores`: 髪質・頭皮・白髪の履歴（推移グラフ用）。
- 取得: ホーム表示時に profile / records サマリ / 次回予約 / plan を1回で取得。
